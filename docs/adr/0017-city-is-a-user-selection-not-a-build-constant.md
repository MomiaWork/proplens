# ADR-0017: 縣市是使用者的選擇，不是編譯期常數

## Status

Accepted

## Context

到 ADR-0016 為止，整個引擎都預設「台中市」：地址前綴、行政區代碼表、
五份資料檔名、`outside-taichung` 這個查詢結果狀態，全部寫死。要加入第二個
縣市（新竹市）有兩條路：

1. 每個縣市各出一個 app（或 build flavor），沿用寫死的作法。
2. 把縣市變成一個執行期的值，使用者在 app 裡選。

同時，各縣市的資料可得性差異很大，這一點直接影響設計：

| 資料 | 台中市 | 新竹市 |
| --- | --- | --- |
| 實價登錄 | 全國同一個 zip，`b_lvr_land_a.csv` | 同一個 zip，`o_lvr_land_a.csv` |
| GIS門牌 | 市府開放平台每月更新，可自動抓 | 開放平台無可定址的搜尋網址，查無可自動抓的資源 |
| 學區表 | 開放平台 CSV，可自動抓 | 僅以 PDF 公告於教育處網站 |
| 都市計畫分區 | 手動下載 Shapefile | 手動下載 Shapefile |

還有一個地址格式差異：**新竹市的地址不寫行政區**。日常寫法是
「新竹市中華路二段445號」，實價登錄則把縣市寫兩次
（「新竹市新竹市西大路７２巷４７弄３號」），`鄉鎮市區` 欄位一律是「新竹市」
而非東區／北區／香山區。台中市則一律有行政區。

## Decision

**縣市是執行期的使用者選擇。** `src/core/cities.ts` 是唯一寫下縣市差異的
地方，app 上方的縣市選擇器直接列出 `CITIES`。

具體約束：

- **每個縣市有自己的五份資料檔**，檔名帶縣市前綴
  （`hsinchu-address-points.sqlite`…）。同一個 GitHub Release 裝得下所有
  縣市，手機只下載使用者選的那一個縣市的 ~200MB。
- **版本記錄是 per city**（`data-versions.json`）。只新增一個縣市的
  release，不該害既有使用者重抓沒變的舊縣市快照。
- **`parseAddress` 收 `city` 參數**，由縣市決定剝掉什麼前綴、查哪張行政區
  代碼表。選錯縣市時前綴會留在街道名上，因此比對不到門牌——寧可查不到，也
  不要誤配到另一個縣市的同名街道。
- **新竹市的行政區代碼表刻意留空。** 既然沒有任何地址會寫出行政區，這張表
  永遠不會被查詢；而未經門牌檔驗證就填進去的代碼，會讓每次查詢都被篩成
  空集合且無聲失敗。
- **`outside-taichung` 改名為 `outside-city`。** 狀態本身不該記得是哪個縣
  市——問的人才知道自己問的是哪個縣市。
- **無法自動抓取的資料來源是「手動來源」，不是缺口。** `tools/citySources.ts`
  區分 `fetched` 與 `manual`；`manual` 的縣市用 `--from <csv>` 餵入人工下載
  的檔案，解析、驗證、寫入 SQLite 的程式碼完全共用。門牌 CSV 改為**依標題列
  對應欄位**而非固定欄位位置，各縣市匯出的 TGOS 門牌 schema 欄序不同也能載入，
  對不上就明確報錯。

## Consequences

- 新增第三個縣市 = `cities.ts` 加一筆 + `citySources.ts` 加一筆 + 產出五份
  檔案上傳 release。程式碼不用改。
- Release 的資產名稱全部改了。**下一個 release 必須用新檔名重新上傳**，舊名
  稱（`address-points.sqlite` 等）不會再被任何版本的 app 讀取。
- Release 裡沒有某縣市的檔案時，`syncCityDataIfNeeded` 在下載任何位元組之前
  就丟 `CityDataNotPublishedError`，app 顯示「該縣市資料尚未發布」且不給重試
  ——重試不會改變結果。
- 新竹市的門牌與學區檔在有人手動取得之前無法產出，因此**新竹市在 app 裡可以
  選，但要等這兩份檔案上傳 release 後才查得到結果**。實價登錄與都市計畫分區
  這兩份已經可以立刻產出。
- 手機上的兩個快取（geocoding、里鄰）刻意跨縣市共用：它們以完整地址字串為
  key，而完整地址一定帶縣市名，切回原本的縣市不會失去已經暖好的結果。
